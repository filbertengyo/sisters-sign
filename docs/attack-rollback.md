# Rollback Attack Demo

The demo of the rollback attack can be viewed in `tests/attacks/rollback_demo.cpp`. The demo shows that the current design has no way of stopping an older possibly vulnerable artifact from being verified. This would allow an attacker with sufficient access to perform a rollback attack in which they would rollback the deployed version of an artifact and introduce a patched vulnerability back into the system. To fix this, a method to identify and stop older artifacts from being signed is needed. The simplest way to implement this would be to add a monotonic version counter that act as a border between passable versions and must-reject versions. A more complete implementation would be to add a version blacklist for outdated versions. Either solution would require the new information (version counter or version blacklist) to be stored as part of the system's trusted state so that an attacker wouldn't be able to tamper it as well.
