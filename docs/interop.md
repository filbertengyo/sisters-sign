# Interoperability

`tests/interop/` checks that sister-sign's key, manifest, bundle and signature formats can be
produced and consumed by an independent implementation: Python
[`cryptography`](https://cryptography.io) and the `openssl` CLI. The Python side builds the
canonical manifest and bundle from the format description (`tests/interop/generate_bundle.py`),
not from sister-sign's code.

Run it with `ctest --test-dir build -R interop --output-on-failure`, or directly:

```sh
cd tests && python3 -m interop.main ../build/sister-sign ../build/interop-results
```

The table and per-case evidence (keys, bundles, manifests) are written to
`build/interop-results/`.

## What is checked

For each algorithm (`rsa-pss-sha256`, `ecdsa-p256-sha256`, `ed25519`), in both directions:

| Direction | Case | What it proves |
|---|---|---|
| external -> sister-sign | keys | A key generated by `cryptography` (PKCS#8 / SPKI PEM) is accepted by `trust add` and `sign`; both sides compute the same keyid (SHA-256 of DER SPKI). |
| external -> sister-sign | bundle | A bundle built entirely in Python (manifest, signature, bundle JSON) verifies as `OK` with `sister-sign verify`. Flipping one signature bit gives `INVALID_SIGNATURE`. |
| sister-sign -> external | keys | `keygen` output loads in `cryptography`, the public key matches the private key, and the keyid matches. |
| sister-sign -> external | bundle | A bundle from `sign` is decoded with strict base64, its manifest is byte-identical to an independently built canonical manifest, and the signature verifies with `cryptography` and with `openssl` (`pkeyutl -rawin` for Ed25519, `dgst -sha256` for ECDSA and RSA-PSS). A modified manifest is rejected. |

Algorithm-specific cases:

- **ECDSA, DER <-> r||s.** OpenSSL and `cryptography` use ASN.1 DER (70-72 bytes). The bundle
  carries a fixed 64-byte `r||s` (big-endian, 32 bytes each). `ecdsa_p256_sha256.py` converts in
  both directions, and the round trip is checked to be the identity. A bundle carrying a
  *mathematically valid* signature in raw DER form is rejected by `verify` with `INVALID_SIGNATURE`.
- **RSA-PSS, pinned salt.** Interop needs PSS with SHA-256, MGF1-SHA-256 and a salt length of
  32. A signature made with the maximum salt length is valid PSS, and is a common library
  default, but `verify` rejects it with `INVALID_SIGNATURE` because the verifier never uses
  `SALTLEN_AUTO`.
